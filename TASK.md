# Индивидуальные задания по backend-разработке

**15 баллов**

Реализуйте три независимых сервиса для работы с пропусками. HTTP API, сущности, DTO, интерфейсы и обработка ошибок уже подготовлены.

Используйте готовые репозитории напрямую: сервисы не должны вызывать друг друга. Можно добавлять методы запросов в репозитории, сохраняя существующие методы, а также вспомогательные классы и методы. Не изменяйте зависимости, модели, DTO, исключения, интерфейсы и сигнатуры сервисов, контроллеры, часы, миграции, конфигурацию и компоненты проверки.

Время представлено в зоне `Europe/Moscow`. Даты API имеют формат `yyyy-MM-dd'T'HH:mm:ss` без смещения. Для получения текущего времени используйте внедрённый `Clock`.

## B1. Получение пропуска

В `PassReadServiceImpl` реализуйте `getById(passId: Long): PassDetailsDto`. Найдите пропуск по идентификатору и верните все его поля и данные владельца во вложенном `VisitorDto`:

- `PassDetailsDto`: `id`, `qrCode`, `validFrom`, `validTo`, `maxEntries`, `revokedAt`, `visitor`;
- `VisitorDto`: `id`, `fullName`, `organization`.

Если организация или время отзыва отсутствуют, сохраните значение `null`. Если пропуск не найден, выбросьте `PassNotFoundException`. Метод не должен изменять данные базы.

Проверить результат можно запросом `GET /api/passes/{id}`.

## B2. Определение статуса

В `PassStatusServiceImpl` реализуйте `status(passId: Long): PassStatus`. Если пропуск не найден, выбросьте `PassNotFoundException`. Получите текущее время из `Clock` один раз за вызов и определите статус по первому выполненному условию:

1. Время отзыва задано — `BLOCKED`.
2. Текущее время раньше `validFrom` — `NOT_STARTED`.
3. Текущее время позже `validTo` — `EXPIRED`.
4. Число входов не меньше `maxEntries` — `EXHAUSTED`.
5. Иначе — `ACTIVE`.

Обе границы срока действия включены. Учитывайте только записи `scan` этого пропуска с направлением `entry` и временем `scannedAt` не позднее текущего. Выходы, будущие сканирования и записи других пропусков не учитываются. Метод не должен изменять данные базы.

Проверить результат можно запросом `GET /api/passes/{id}/status`.

## B3. Отзыв пропуска

В `PassRevokeServiceImpl` реализуйте `revoke(passId: Long): PassRevokeDto`. Если пропуск не найден, выбросьте `PassNotFoundException`.

Если пропуск ещё не отозван, установите время отзыва из `Clock`, отбросив доли секунды, и сохраните изменение в PostgreSQL. Если пропуск уже отозван, оставьте исходное время. Верните идентификатор пропуска и сохранённое время отзыва в `PassRevokeDto`.

Отзыв возможен также для пропуска, срок действия которого ещё не начался или уже истёк, и для пропуска с исчерпанным лимитом. Повторный отзыв должен успешно возвращать первоначальное время. Другие поля и записи изменять нельзя. Публичный метод реализации должен выполняться в транзакции, заданной с помощью `@Transactional`.

Проверить результат можно запросом `POST /api/passes/{id}/revoke` без тела запроса.

## Сдача решения

Получите три кода запросами:

- `GET /code/task1/{participantId}` — код B1;
- `GET /code/task2/{participantId}` — код B2;
- `GET /code/task3/{participantId}` — код B3.

Вместо `participantId` укажите свой ID из задания в учебной системе, а не ID пропуска. После изменения реализации получите соответствующий код заново.

В учебной системе отправьте один ответ из трёх кодов: B1 на первой строке, B2 на второй, B3 на третьей. Не добавляйте подписи; сохраните все цифры и знак минус, если он есть.

Первая неверная попытка сдачи не штрафуется. Каждая следующая неверная попытка добавляет штраф в размере 10% от стоимости задания. Максимальный штраф — 50% от стоимости задания.
